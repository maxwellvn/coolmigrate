For Coolify 4.x

Move an app to another server. One click.

coolmigrate copies an application, its databases, env vars and upload folders from one Coolify server to another, streams every step, and leaves the original untouched until you say so.

$npm i -g coolmigrate && coolmigrate

What gets copied

Everything Coolify knows about the app.

Not a screenshot of settings. The actual definition, data and files, recreated through the Coolify API and streamed over SSH.

01

Application

Repo, branch, build pack, Dockerfile path, ports, health check, resource limits, pre and post deploy commands, domains.

02

Databases

PostgreSQL, MySQL, MariaDB, MongoDB, Redis. Same image and credentials. Dump piped straight from container to container, no temp files.

03

Env vars

All of them, with database hostnames and any renamed credentials rewritten to point at the new copies.

04

Storage

Persistent volumes and upload directories tar-streamed into place before the first deploy, so nothing is missing on first boot.

05

Build log

Coolify's own deployment log tails into the same view, line by line, until the app reports running.

06

Verification

Table, collection and key counts compared between source and destination. Mismatches are flagged, not hidden.

How it works

Six steps, each one logged.

1 / 6

Preflight

Measures the data to move, checks free disk and memory on the destination, confirms Coolify can actually reach that server. Refuses early instead of failing late.

2 / 6

Project and environment

Creates or reuses the destination project and environment.

3 / 6

Databases

Creates each database with the same engine and image, waits until it answers, then streams the dump in. Redis snapshots are installed so an append-only instance loads them correctly.

4 / 6

Application

Recreates the app definition through the API, bound to a GitHub App on the destination that can see the repo.

5 / 6

Storage and env vars

Registers every mount, copies the files, then pushes env vars with hostnames rewritten.

6 / 6

Deploy

Queues the deployment and tails Coolify's build log until the app is running.

Safety

The source is never modified.

A migration is a copy. You verify the new one, move DNS, then stop the old one from the same page. Start it again if something is wrong. Delete only when you type the word.

Resume
Every completed step is checkpointed. A failed run continues from where it stopped.
Preflight
Disk, memory and server reachability are checked before anything is created.
Sanitize
Identifiers and passwords the API rejects are adjusted and logged. Env vars follow.
Live state
Both sides show current status. Buttons enable only when the action makes sense.
Secrets
Tokens and passwords AES-256-GCM encrypted on disk. Server bound to localhost.
Leftovers
Anything created before a failure is listed and removable with one action.

Install anywhere

One command, then a browser tab.

Runs on macOS, Linux and Windows with Node 20 or newer. Settings live in your home folder, so the same instances are there every time.

$ npm i -g coolmigrate
$ coolmigrate
coolmigrate running at http://127.0.0.1:3456  (data: ~/.coolmigrate)  Ctrl+C to stop

# options
$ coolmigrate --port 4000 --no-open
$ coolmigrate --data /srv/coolmigrate
